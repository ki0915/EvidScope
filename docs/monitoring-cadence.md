# 모니터링 시간 기준

화면의 조회 주기, 차트 한 점의 집계 기간, 이벤트 수집·탐지 주기를 구분한다. 아래 값은 현재 파일럿의 용도별 초기 설정이며 보편적인 표준이나 사고 탐지 SLA가 아니다. 실제 운영에서는 출처의 정상 발생 빈도, 허용 탐지 지연, 보존량 및 동시 감사자 수에 따른 조회 부하를 측정해 조정해야 한다.

| 용도 | 조회 범위 | 한 점의 집계 기간 | 자동 조회 간격 |
|---|---|---|---|
| 운영 모니터링 — 기본 | 최근 1시간 | 1분 | 1분 |
| 일간 추세 | 최근 24시간 | 5분 | 5분 |
| 주간 검토 | 최근 7일 | 1시간 | 15분 |
| 상세 조사 — 명시적 선택 | 최근 10분 | 30초 | 30초 |

5초 조회는 탭당 이론상 시간당 720회였지만 기본 1분 조회는 약 60회다. 각 인증 조회가 감사 접근 이력에도 남는 현재 구조에서 불필요한 화면 재조회와 이력 증가를 줄인다. 실제 간격은 응답 완료 후 타이머를 시작하므로 응답 소요 시간만큼 길어진다. 상세 조사도 30초 미만으로 반복 조회하지 않는다. 일간·주간은 순간적인 변동보다 추세를 보도록 집계 기간을 넓힌다.

이벤트는 기존 수집 경로에서 도착할 때마다 접수하며 worker 분석 주기는 이번 변경으로 바뀌지 않는다. 화면 표시까지는 선택한 조회 간격과 처리 지연이 발생한다. 긴 집계 구간에서 짧은 급증이 합산되므로 상세 조사를 함께 사용한다. 마지막 구간은 미완성임을 표시한다.

조회 실패는 마지막 성공 시각과 자료를 유지하며 현재 값으로 가장하지 않는다. 재시도 간격은 선택한 주기의 2·4·8배로 늘리고 최대 1시간으로 제한한다. 401/403은 자동 재시도를 중단한다. 일시정지, 숨긴 탭, 화면 이탈·로그아웃에서는 새 주기 요청을 멈추고 이전 비동기 응답을 폐기한다.

현재 최근 5분 내 수신 여부는 단순 참고 상태이며 장애 임계치가 아니다. 하루 한 번 보내는 출처를 이 기준만으로 장애로 판단해서는 안 된다. 출처별 기대 주기·heartbeat 계약과 알림 SLA는 아직 구성 기능이 없다.

집계는 테넌트별 현재 보존된 조회 사본의 수신 시각 기준이다. 미등록 AI의 활동이나 원본 실행 사실을 확정하지 않으며 파기로 과거 수치가 감소할 수 있다. 서버 원본을 매번 검증하는 서명 감사 보고서를 대체하지 않는다. Kubernetes 그래프는 기존 실측 스냅샷으로 유지하며 이 자동 조회와 별개다.

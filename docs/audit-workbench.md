# 실무 감사자 안내

EvidScope의 기본 화면은 **행동 조사함**이다. 한 행동의 관측 기록을 모아 검토할 대상을 고르고, 사람의 판단에 사용한 근거와 남은 불확실성을 기록한다. 외부 업무 실행을 승인하거나 차단하는 화면이 아니다.

## 일상적인 조사 순서

1. **대상 선택:** 행동·행위자·도구·목적지를 검색한다. `검토 필요`에는 미검토, 새 증거로 재검토가 필요한 행동, 판단을 유보한 행동이 포함된다. 집계는 검색어에 일치하는 행동 기준이며 전체 조직 AI 사용률이 아니다.
2. **출처 대조:** `행동 조사 열기`에서 AI 요청/자기보고, 도구 실행, 서비스 결과, 당시 권한과 승인을 대조한다. 성공과 실패가 함께 있으면 혼재 상태를 유지한다. 이전 자동 평가와 현재 수집된 결과를 구분한다.
3. **참고 자료 확인:** 자료 ID, 버전, 해시, 제출 출처와 참조 역할을 비교한다. 합성 사례의 product-guide는 AI 자기보고 v2와 도구 기록 v1이 다르다. 실제 사용·원문 일치는 별도로 확인해야 한다.
4. **사건 검토:** 연결 사건을 열거나 새 사건을 만든다. 실제로 사용할 근거에 체크하고 판단을 뒷받침하는지, 상충하는지, 배경인지 표시한다. 판단은 `문제 확인`, `검토 범위에서 문제 미발견`, `판단 유보` 중 고른다.
5. **범위와 한계 기록:** 판단 사유, 직접 확인한 범위, 확인하지 못한 사항, 다음 검토 일시를 기록한다. 첫 두 결론에는 최소 한 개의 같은 행동 근거가 필요하다. 빈 근거의 정상·준수 결론을 만들지 않는다. 판단 유보는 근거 없이도 부족 상태를 기록할 수 있다.
6. **후속 조치:** 담당자·댓글·기한이 있는 과제를 관리한다. 사건 종결 상태와 인간 판단은 별개다. 기존 사건 종결 API는 종결 사유를 요구하며, 종결 자체가 충분한 검토·위험 해소를 의미하지 않는다.
7. **보고:** 사건 보고서에서 동일 스냅샷의 서명 JSON과 읽기용 Markdown을 내려받는다. 외부 감사자에게는 검토 범위·한계와 함께 별도 신뢰 경로로 공개키를 전달한다.

## 판단은 시점에 묶인다

서버는 판단 작성자와 시각, 당시 관측 이벤트의 ID/원장 순번/해시 목록, 분석 버전 목록과 체크포인트를 자동 기록한다. 선택한 논거와 당시 화면의 전체 관측 목록은 구분되며 원문을 판단 기록에 복사하지 않는다. 과거 판단은 새 판단으로 덮어쓰지 않는다.

늦은 증거, 새 분석 결과, 정책 변경으로 인한 분석 버전 변경, 보존 종료에 따른 원문 파기, 재검토 기한 도래 시 재검토로 표시한다. 오래된 근거 화면으로 판단을 제출하면 HTTP 409로 거부한다. 메모 추가·단순 조회는 증거 문맥을 바꾸지 않는다.

이 보호는 **근거 변경 충돌**을 탐지한다. 동일한 근거를 두 사람이 동시에 검토하는 예약 잠금·정족수·서로의 결론 승인 절차는 구현하지 않았다. 판단은 모두 보존되며 최근 기록을 표시한다. 사건별 세분화 접근 정책과 운영 SSO는 별도 작업이다.

## 독립 검증

```powershell
node scripts/verify-case-report.mjs <사건보고서.json> <별도보관-public-key.pem>
node scripts/verify-case-report.mjs <사건보고서.json> <별도보관-public-key.pem> <별도보관-checkpoint.json>
```

검증기는 `canonical({format,snapshot})`의 Ed25519 서명, DER SPKI 공개키 SHA-256 지문, 스냅샷과 체크포인트의 테넌트 결합을 검사한다. 키를 보고서에서 받아 신뢰하지 않는다. 외부 체크포인트는 정확한 스냅샷 비교이며, 제공하지 않으면 정상 서명된 과거 보고서로의 교체는 탐지할 수 없다. 성공 exit 0, 변조·다른 키·외부 체크포인트 불일치는 exit 1이다.

서버는 발급 전에 서명 원장을 순회하며 테넌트 이벤트 사본 및 이 사건·분석·판단 사본을 원본과 대조한다. 변조된 사본을 정상 보고서로 재서명하지 않는다. 보고서 자체는 사건 스냅샷의 서버 서명이다. 전체 체인의 포함·완전성은 별도 전체 증적 export와 `scripts/verify.mjs`로 검증한다. Markdown은 서명되지 않은 읽기용 사본이다.

## 용량과 운영 범위

- 조사함은 페이지당 최대 100개 행동을 반환한다. 상태별 정확한 집계를 위해 검색에 일치하는 행동들을 순회하므로 대규모 검색 인덱스·동시 감사자 용량은 별도 검증이 필요하다.
- 사건 검토는 1,000개 이벤트, 100개 분석 이력, 200개 판단, 문맥 8 MiB, 단일 원장 기록 2 MiB 한도를 적용한다. 보고서는 10 MiB 한도다. 넘으면 HTTP 413으로 거부하며 조용히 생략하지 않는다. 긴 사건을 분리할 업무 기준은 조직에서 정해야 한다.
- 조회·검토·서명 검증은 SQLite 단일 vault의 자원을 공유한다. 원장 순회는 데이터 증가에 따라 비용이 늘어난다. 원장 외부 봉인·키관리·실제 공급자 connector·운영 IdP SSO·Kubernetes HPA/CNI/Pod 복구 검증은 미완료다.
- 실제 조직 데이터나 법률 판단을 사용하지 않고 합성 사례로 검증했다. 사람의 자유 기재 메모·보고서 사본에는 별도의 보존 정책이 필요하다.

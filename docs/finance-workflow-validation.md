# 독립 프로세스 금융 감사 실증

기존 수집·금융 대조·고정 보고서 API를 실제 HTTP로 검증하는 합성 업무 fixture다. `finance-workflow-pilot.mjs`가 새 임시 환경의 vault·ingress·audit·worker를 시작하고, `finance-workflow-producer.mjs` 세 자식이 승인 상태, 결정적인 AI 계산, 업무 적용 상태를 각각 생성한다. 부모는 요청과 설정을 전달하며 완성된 이벤트를 전달하지 않는다. AI 실행은 `workflow-ai`, 업무 결과는 `workflow-business` 자격으로 직접 수집된다.

## 실행

Node 24.15.0 계열과 프로젝트 의존성이 필요하다. 기존 live 서비스·GPU·Cowork·DLP 설정을 변경하지 않는다. 숫자 loopback과 임의 포트를 사용한다.

```powershell
node scripts/finance-workflow-pilot.mjs --host ::1 --output reports/finance-workflow-manual-01.json
```

출력 파일은 새 경로여야 한다. 같은 파일을 덮어쓰지 않는다. 같은 입력임을 고정하려면 첫 영수증의 `fixtureSha256`을 다음 실행의 `--expected-fixture-hash`로 전달한다. 각 실행의 임시 디렉터리에 전체 영수증, 사건별 서명 보고서, 별도 신뢰 공개키와 합성 증거 데이터가 남는다. 설정 파일에는 임시 자격이 있으므로 공개 보고서로 공유하지 않는다. 공개 영수증에 토큰·HMAC 비밀이 포함되지 않는지 실행기가 검사한다.

## 검사 범위

| 입력 | 확인할 결과 |
| --- | --- |
| 공급사 v1 / 현재 모델 v2 | 공급사 근거 적용 범위 재검토 |
| 철회 뒤 실행 | 권한 불일치와 정확한 출처·이벤트 근거 |
| 차단 기록 / 별도 업무 프로세스 성공 | 차단·업무 결과의 충돌 |
| 건별 승인 불필요 자동 처리 | 승인 누락 경보 없음 |
| 실행 전 발급 / 실행 기록 뒤 수신한 승인 | 늦은 증거와 사후 승인 구별 |
| 실행 없음 / 공급사 문서 복구 불가 | 증거 부족 유지 |
| 잘못된 HMAC, 다른 시도 승인, 다른 모델 증빙, 다른 테넌트 결과 | 수신 거부 또는 잘못 연결되지 않은 근거·경계 |

프로듀서 상태 digest와 출력 기록의 hash, finding의 원본 참조, 고정된 보고서 내용을 대조한다. 사건 보고서는 embedded key만 믿지 않고 임시 환경 초기화 때 따로 확보한 공개키로 검증한다. 발생 시각은 합성 clock이며 지연 승인의 HTTP 수신 순서와 구별해 기록한다. 모든 자식의 종료를 확인하며, 마지막 API 호출 이후의 비정상 서버 종료도 성공 판정을 막는다.

## 실제 검증 근거와 한계

2026-10-06 최종 반복·별도 서명 검증의 근거는 [완료 보고서](../reports/finance-workflow-completion-20261006.md)에 있다. 이전 `finance-pilot.mjs`의 서명 자식·부모 서비스 호출 방식과 구별되는 실증이다. 제품 API·법률 판정·새 승인 엔진을 추가한 변경이 아니다.

같은 사용자 계정의 로컬 프로세스 분리는 별도 호스트나 관리자의 신뢰 격리를 입증하지 않는다. 합성 AI 함수는 LLM이나 실제 신용평가 모델이 아니다. 차단 기록은 합성 제어 보고이며 강제 정책 게이트웨이를 구현하지 않는다. 실제 금융기관·AGT 운영 연동, 감사자의 검토 시간, 장기 보관 운영, 경쟁 도구와의 동일 입력 비교는 이 실증에서 확인하지 않았다. 서명은 출처 주장의 진실성·법률 충분성을 보증하지 않는다. 봉인된0.1.3 배포본은 보존하고 새 fixture는 개발 작업 트리에 추가했다.

  "실행 중 에이전트"는 5분·15분·1시간·24시간 안에 기록이 들어온 에이전트를 최근 순으로 보여 주고 30초마다 다시 읽습니다. AI 검토실에 "모델 현황" 탭이 생겼고,
  이벤트·발견·사건 목록은 기본으로 최근 기간만 보여 주고 "이전 기록 더 보기"로 과거를 이어 읽습니다.
- **어떤 문제였나:** 오너가 예전 PC 사본을 직접 써 보고 낸 피드백: 지금 어떤 에이전트가 돌고 있는지 안 보임, 옛 기록이 최신 기록을 덮음, 위협·검토 대기·거버넌스 지원이
  안 보임, 학습이 안 보여 감사 AI가 학습됐는지 알 수 없음(작업 메모).
- **고민한 점:** "활동"을 heartbeat(생존 신호)로 오해하지 않게 "기간 안에 기록이 수신됐다는 뜻"이라고 화면에 적었습니다. 거버넌스 열은 "증거 있음"만 세고 "준수"라는
  말을 쓰지 않습니다. 원장 밖에서 확인할 근거는 "여기서 세지 않음"으로 따로 표시. "마지막 방문 이후 새 발견" 기억은 브라우저에만 두고 서버로 보내지 않습니다.
  모델 현황은 어댑터가 붙지 않았다는 사실과, 학습 기록이 항상 유보 기준선보다 낮아 승격하지 않았다는 사실을 그대로 보여 줍니다.
- **해결 방법:** 이벤트 수신 시각 색인 범위 하나만 최신순으로 읽고 최대 20,000건·32MiB에서 자르며, 잘리면 "하한값"이라고 표시. 목록 API에 since·until·cursor·order=desc 페이지 추가(기존 호출은 그대로).
- **결과:** 이벤트 10만 건(30일 분산) 테넌트에서 실행 중 에이전트 응답 15분 약 3~4ms, 1시간 약 4~7ms, 24시간(3,331건) 약 35ms(`docs/feature-guide.md`).
- **포트폴리오 한 줄:** 사용자 피드백("지금 뭐가 돌고 있는지 모르겠다")을 받아 위협·검토 대기·증거 현황을 한 화면에 모은 첫 화면을 만들고, 10만 건에서 35ms 안에 응답하게 했다.

## UI/UX 원칙 정리

- **판정이 아닌 것은 판정처럼 보이지 않게.** "증거 있음 ≠ 준수", 자동 분류는 "읽기 도움", 실행 중 에이전트의 "활동 ≠ 생존 신호", 참고 자료는 "자기 보고"라고 화면에 직접 적습니다
  (`docs/feature-guide.md`, `src/log-explorer.mjs`, `1dbe574`).
- **0과 빈 화면을 안전으로 보이게 하지 않기.** "기록이 없다는 것은 안전하다는 뜻이 아닙니다", "미관측은 통과가 아닙니다", 잘린 수치는 "하한값"(`public/ops.js`, `7e40308`, `docs/first-release-execution-plan-20260912.md`).
- **목록은 촘촘하게, 상세는 한 번 더.** 경보 목록은 기준 번호 한 줄 + hover, 상세에는 전체 제목. 로그 행은 그 자리에서 펼침(`1dbe574`, `794f210`).
- **최근 것 먼저, 과거는 숨기되 지우지 않기.** 기간 선택·"이전 기록 더 보기"·실시간 보기(`7e40308`, `794f210`).
- **실제와 데모를 섞지 않기.** 기본은 실제 기록, 합성은 표시하고 원장은 그대로(`d8ac206`).
- **조회 비용을 의식하기.** 용도별 조회 주기, 숨긴 탭·다른 화면에서 정지, 실시간은 켤 때만, 무거운 응답은 앞부분만 + 전체 건수(`docs/monitoring-cadence.md`, `d8ac206`, `794f210`).
- **권한은 서버, 화면은 텍스트.** 역할·4-eyes·게이트는 서버가 지키고 화면은 서버 값을 텍스트 노드로만 그립니다(`e00b4d0`, `public/ops.js` 머리말).
- **익숙한 도구의 문법은 빌리고, 이미 있는 도구는 다시 만들지 않기.** Datadog/Grafana의 facet·히스토그램 drilldown·live tail·다크 테마는 빌리되, trace 화면은 Langfuse·Phoenix로 연결(`794f210`, `2873777`).

# 개발 기록 (업데이트별)

EvidScope를 만들면서 업데이트마다 무엇이 바뀌었고, 어떤 문제가 있었고, 어떤 대안을 놓고 고민해 어떻게 풀었는지를 남긴 기록입니다. 포트폴리오와 개발 과정 글을 쓸 때 언제든 참고하도록 만들었습니다. 이력서·면접 준비용으로 한 파일에 압축한 요약은 [포트폴리오 컨텍스트](../portfolio-context.ko.md)에 있습니다.

- 기준일: 2026-10-17
- 기록 안의 "사용자"와 "오너"는 프로젝트 오너를 뜻합니다.
- 숫자에는 모두 출처(커밋 `sha7`, 저장소 문서 경로, 저장소 밖 작업 메모)를 붙였습니다. 출처 없이 짐작한 것은 "(추정)"으로 표시했습니다.
- 학습·평가 데이터는 설계로 만든 합성 데이터와 공개 데이터입니다. 사람이 검토한 라벨은 없습니다.

## 프로젝트 전체에서 굳어진 원칙

- **만점은 먼저 의심한다.** 라운드마다 적대적 재감사를 먼저 했고, 세션 판정의 첫 "1.0"도 누수와 라벨 지름길로 무효화했다. 모든 판정 회차에 모델 없는 단순 기준선과 누수 검사를 넣었다.
- **틀리면 안 되는 일은 코드가, 맥락 판단은 모델이.** 위험 규칙·순서 규칙·내용 검사·법 조항 계산·증거 서명은 결정적 코드가 한다. 모델은 규칙 경보를 지울 수 없고, 낮추려면 두 판정 모델이 모두 동의해야 한다.
- **모른다는 것을 상태로 표시한다.** "기록이 없다는 것은 안전하다는 뜻이 아닙니다", `not_replayable`, "당시 정책 미확인"처럼 확인하지 못한 것을 성공이나 실패로 뭉개지 않는다.
- **바퀴를 다시 만들지 않는다.** OTLP·C2SP·DSSE·in-toto·OCSF 같은 표준에 붙이고, 직접 만든 부분은 실제 도구와의 상호운용 시험으로 확인한다. 관측 화면은 Langfuse·Phoenix에 맡기고 그 위에 검증 결과를 얹는다.
- **측정이 먼저이고, 보장은 협상하지 않는다.** 처리량은 프로파일링으로 병목을 찾아 올렸고, 영속 보장과 검증 형식은 바꾸지 않았다. 목표 미달도 숫자로 남겼다.
- **데이터 경계를 먼저 정하면 외부 자원도 쓸 수 있다.** 실제 수집 기록은 PC를 떠나지 않고, 임대 GPU에는 합성 시나리오와 공개 데이터만 보낸다.
- **사용자 피드백은 바로 화면으로.** "지금 뭐가 돌고 있는지 모르겠다", "UI가 별로", "참고 내용을 알 수 없다"가 각각 첫 화면, 다크 운영 콘솔, 세션 참고 자료로 이어졌다.

## 진행 중이거나 아직 안 된 것

- 판정 4회차 Qwen 학습과 5회차(LLM 보안·에이전트 간섭·EvidScope 기록 변조) 결과
- PC(RTX 3080 12GB) 배포: JEV-9B가 모든 세션을 보고 걸린 세션만 Qwen3-4B로 넘기는 구성, 실제 속도·메모리·실제 세션 오탐률 측정
- 학습이 끝난 뒤 오케스트라(규칙 → JEV → Qwen → 서명된 조항 표) 전체를 처음부터 끝까지 한 번 실행
- 거버넌스 판정 자리(gpt-oss-safeguard-20b, 학습 없이 조항 요구사항을 정책으로 주는 방식)
- 판정 이유를 문장으로 쓰는 reason 필드, 프롬프트 검사(오너 승인 대기), 사건 묶기, Slack·메일 알림, hook 자기 보고를 교차 확인할 독립 관측

## 새 업데이트를 기록하는 법

업데이트가 끝나면 해당 분야 파일 끝(또는 날짜 순서에 맞는 자리)에 위 형식으로 한 항목을 더하고, 이 문서의 "한눈에 보는 흐름"과 "대표 수치", [포트폴리오 컨텍스트](../portfolio-context.ko.md), 저장소 [README](../../README.md)의 수치를 함께 고칩니다. 공개 저장소이므로 비밀값, 개인 경로, 임대 장비 주소, 실제 수집 기록 내용, 공격 형태 명령은 적지 않고 종류와 개수로만 적습니다.

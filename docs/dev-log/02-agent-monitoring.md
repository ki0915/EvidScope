> 용어 한 번에 정리
> - **hook(훅):** Claude Code·Codex 같은 AI 도구가 도구(명령 실행, 파일 읽기·쓰기 등)를 쓰기 직전·직후에 자동으로 실행해 주는 사용자 스크립트.
> - **facet(패싯):** 검색 화면 왼쪽에 "에이전트·분류·상태"처럼 값별 개수를 보여 주고 눌러서 거르는 목록.
> - **live tail(실시간 보기):** 새 로그가 들어오는 대로 목록 맨 위에 붙여 보여 주는 방식.
> - **OCSF:** 보안 이벤트를 여러 SIEM(보안 로그 통합 분석 도구)이 공통으로 읽도록 정한 공개 스키마.
> - **평가 엔진 vN:** 기록 하나하나를 규칙으로 판단하는 코드의 버전. 버전이 원장에 함께 서명되어, 나중에 같은 결과가 나오는지 다시 계산(재생)할 수 있습니다.
> - **대응표(mapping) vN:** 어떤 경보·기록이 어떤 법·인증 항목을 검토할 때 볼 자료인지 적은 서명된 표.

- **어떤 문제였나:** 경보만으로는 이미 일어난 뒤에 압니다. 오너는 차단 수준 카드에서 "확실한 것만 차단" / "경보만" / "고위험 전부 차단" 중 첫 번째를 골랐습니다.
- **고민한 점:**
  - 오차단은 개발을 멈춥니다. 상황과 관계없이 문제인 것만 막고 나머지는 경보로 둡니다.
  - 읽기와 고치기를 구분: AI 설정 파일을 읽는 것(보여 주기만 하는 명령 포함)은 막지 않습니다. 단, EvidScope hook 설정은 수집 자격이 들어 있어 읽기도 막습니다.
  - 규칙 팩을 읽지 못하면 아무것도 막지 않고 로그만 남깁니다(작업을 멈추지 않는 쪽을 택한 fail-open — 대신 그 사실이 기록됨).
  - Codex는 거부 응답 형식을 PC에서 확인하지 못해 경보만 냅니다. 정말 필요한 작업이면 사용자가 직접 실행합니다.
- **해결 방법:** 차단 판정 62줄 + 테스트 149줄(`agent-hook-guard.test.mjs`), 설치 시 hook이 읽을 규칙 팩도 함께 복사.
- **결과:** PC에 설치된 hook에서 확인(10-17): 설정 수정 시도 → 거부 응답·정상 종료·"차단됨" 기록 대기열 저장, 설정 읽기 → 아무 출력 없음(통과)(작업 메모).
- **포트폴리오 한 줄:** 감사 도구 무력화·보안 해제·비밀 즉시 전송처럼 "맥락과 무관하게 확실한" 행동만 실행 전에 막고, 막은 사실까지 원장에 남기는 최소 차단 모드를 설계·검증했다.

# EvidScope 서비스 개선 계획

2026-09-08. 목표는 사람이 AI 행동·정책 근거·관측 공백을 비교하고 조사할 수 있는 서비스다. 감사 영역에 LLM 실행기를 넣지 않고 업무 실행과 증적 보관을 분리한다. 아래 완료 조건은 구현 및 검증 전에 정했다.

## 1. 운영 현황과 조사 (현재 작업)

- 24시간·7일·30일·전체 보존 기간 선택, 위반·근거 부족·재검토·미활동 에이전트 필터와 우선순위 정렬.
- 기간 내 처음 관측된 행동을 집계하되, 그 행동의 기간 밖 권한·승인·후속 증거까지 최신 평가에 사용한다. 과거 당시의 점수라는 인상을 주지 않는다.
- 에이전트별 정책 상태 추이와 구간 선택 → 행동 근거 조사. 최근 100개 제한 대신 페이지로 모든 집계 행동을 조회한다.
- 판정 가능 분모, 평가 범위, 예외, 판단 유보를 유지한다. 에이전트 미귀속 및 다중 귀속은 별도로 표시한다.
- 완료 조건: 시간 경계·외부 기간 근거·0분모·테넌트 격리·필터·전체 페이지·차트 합계 검증, 실제 HTTP 및 브라우저 확인. 실패·빈 상태에서 이전 집계를 새 결과로 표시하지 않는다.

## 2. 에이전트 관리

- 소유자, 목적, 환경, 실행기 종류, 외부 정책 참조, 수집 기대 주기를 가진 등록 정보와 변경 이력.
- 인증된 source와 보고된 actor, 등록된 신원을 구분하고 연결 근거를 표시한다.
- 외부 정책 할당을 기록하며 실행 권한이나 승인 토큰을 발급하지 않는다.
- 완료 조건: 역할별 변경 권한과 변경 감사 기록, 신원 충돌, 정책 변경 후 재검토, 수집 미활동과 장애의 구별 검증.

## 3. 실제 에이전트 연동

- 로컬 에이전트 실행 환경을 감사 프로세스와 분리하고 도구 측 독립 기록을 대조한다.
- 그 다음 Codex 공식 실행 이벤트용 수집기를 연결한다. 로컬 모델 시험 성공과 Codex 연결 완료를 구별한다.
- 정상, 정책 위반, 승인 근거 없음, 참조 충돌, 중복, 늦은 기록, 수집 장애를 반복 시험한다.
- 완료 조건: 시나리오별 생성·전송·접수·분석 건수와 지연·손실 확인, 업무 실행 비차단 및 수집 자원 상한 확인. 실행 이벤트만으로 실제 외부 효과나 내부 사고 과정을 입증하지 않는다.

## 4. 감사 보고서와 운영 배포

- 선택 기간, 산정 기준 버전, 근거 참조, 제외 사유, 인간 검토를 감사 보고서에 연결한다. 조회 집계와 서명 증거를 구별한다.
- 독립 checkpoint 및 복구 절차, 수집·조회 부하 분산과 worker 복구를 실제 Kubernetes에서 검증한다.
- 저장소 HA는 현재 미완료다. 현재 단일 vault 저장소의 복구 시간·손실 범위를 먼저 측정하고 별도 HA 변경을 평가한다.
- 완료 조건: 사전 명시한 부하·장애 조건에서 수신/저장/분석 대조, 무결성·복원·권한 검증. 기존 timeout과 네트워크 검증 한계를 보존한다.

## 우선순위 및 범위

1 → 2 → 3 → 4 순으로 진행한다. 단계별 실행 결과를 보고하고 완료·미검증을 구별한다. 기간은 작업 순서이며 확정 납기 약속은 아니다. 현재 단계에서는 운영·공유 배포, 유료 공급자 연결, 규정 내용 변경을 수행하지 않는다. 전체 제품의 운영 적합성이나 법적 준수 인증을 의미하지 않는다.

## 비용 원칙 (사용자 추가 요구 반영)

- 수집, 집계, 정책 점검, 그래프, 감사 내보내기는 일반 프로그램으로 처리한다. 이를 위해 LLM을 상시 호출하지 않는다.
- AI 시험은 기존 로컬 모델과 PC를 먼저 사용하고 작업이 있을 때만 추론한다. 외부 API 요금은 없으나 CPU·메모리·저장소·전력·유지보수 비용은 존재한다.
- 별도 실행기는 감사 권한 분리를 위한 프로세스이며 유료 모델 도입을 뜻하지 않는다. 무제한 반복·상시 추론·모델별 유료 구독을 기본값으로 삼지 않는다.
- Codex 수집기 구현과 Codex 추론 사용 비용을 구분한다. 현재 요금·계정 한도 검증 없이 무료나 정액 범위 보장을 하지 않는다.
- 유료 API·서버 증설은 로컬 시험의 품질·처리량·자원 실측으로 필요성을 확인한 뒤 별도 승인 범위에서 결정한다.

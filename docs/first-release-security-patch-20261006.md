# v0.1.1 거버넌스 변경 권한 보안 패치

2026-10-06. v0.1.0 이후 독립 HTTP 검토에서 감사자 계정으로 한국 거버넌스 시스템·사람 평가·과제를 변경할 수 있는 권한 결함을 확인했다. 자산·문서 변경과 동일하게 검토자 또는 관리자 권한을 요구하도록 수정했다. 법령 조건이나 사람의 증거 충분성 판정 기준을 바꾼 패치는 아니다.

## 권한과 검증

- 감사자는 시스템·평가·과제를 조회하고 조사·불변 보고서 발급을 수행한다. 해당 세 변경 API는 403으로 거부한다.
- 검토자와 관리자는 시스템 등록, 평가 작성, 과제 변경을 수행한다. 근거 없는 종결은 기존대로 409로 거부한다.
- 수집원과 내부 worker도 사람의 거버넌스 판단을 변경할 수 없다. OIDC의 서버 역할 바인딩도 같은 검사에 적용된다.
- 실제 감사 게이트웨이·직접 vault 요청 30개 거부와 서명 상태 불변, 검토자·관리자 성공, 재시작, 테넌트 격리를 새 회귀에서 검증했다. 수정 후 소스 전체 765/765, 독립 권한·금융·OIDC 검토 15/15, 버전 실행기·권한 집중 5/5가 통과했다.

최종 패치 설치본은 전체 **758/758**, 10회 반복은 **매회 39/39, 총 390/390**을 통과했다. 재빌드한 실제 Linux 배포 이미지도 핵심 **39/39**를 통과했다. 증거는 `reports/security-release-20261006-r2-retry/`에 제공한다. ZIP과 이미지의 SHA-256 및 추출 후 파일 대조는 releases의 별도 distribution JSON과 SHA256SUMS에서 확인한다. 원래 v0.1.0 아카이브는 당시 시험 근거로 보존하며, 운영 파일럿에는 이 패치를 사용한다.

Windows의 긴 설치 경로에서 Git diff가 실패하는 문제도 별도 재현해 수정했다. 이 프로그램의 Windows Git 호출에만 `-c core.longpaths=true`를 적용하며 시스템 전역 Git 설정은 바꾸지 않는다. 실제 긴 경로 회귀와 기존 coordinator 기능을 설치본에서 검증했다.

처음 반복의 4회차 fetch 실패, 설치 검사에서 일시적인 lease rename EPERM, IPv4 loopback의 listen EFAULT는 이전 실패 기록으로 보존했다. EPERM의 원인은 확정하지 못했으며 분리 재실행은 5/5를 통과했다. 최종 Windows 검사는 IPv6 loopback을 명시해 실행했다. 실패한 시도를 최종 통과 회차에 포함하지 않는다. 설치 전체는 배포하지 않는 개인 학습 실험 3개 파일의 8개 검사를 제외한 범위이며, 제외 목록과 이유는 release-manifest.json에 명시한다.

## 교체

1. 실행기를 종료하고 [백업·복구 안내](first-release-20261006.md)에 따라 데이터와 키를 보관한다. 다른 인스턴스가 같은 SQLite 데이터 디렉터리를 동시에 사용하지 않게 한다.
2. v0.1.1 ZIP을 새 디렉터리에 풀고, 기존 `EVIDSCOPE_LOCAL_DIR`·HOST·PORT_BASE를 지정하여 `npm start`로 실행한다. 의존성이 동봉되어 있으며 Node 24.15.x가 필요하다.
3. 네 서비스의 `/healthz`·`/readyz` 및 인증된 시스템 조회를 확인한다. 감사자 변경 403, 검토자 변경 허용을 확인한다. 데이터·자격·키를 새로 생성하지 않는다.

이 패치는 통제된 파일럿의 권한 경계를 보강한다. 공개 배포·실제 금융기관 연동·법률 인증·새 학습 후보 품질 승격은 별도 검증 대상이다.

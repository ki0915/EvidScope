# EvidScope 포트폴리오 컨텍스트

이력서·포트폴리오·면접 준비를 돕는 도구(이력서 비서 등)가 이 프로젝트를 이해하도록 한 파일에 모은 요약입니다. 세부 근거와 업데이트별 기록은 [개발 기록](dev-log/README.md)에 있습니다.

구조화된 데이터가 필요하면 아래 두 파일을 읽으면 됩니다. 둘 다 [개발 기록](dev-log/README.md)의 항목 73개에서 생성되며, 항목 번호(EL-07, JM-19 등)로 서로 이어집니다.

- [career-profile.json](dev-log/career-profile.json): 프로젝트 카드, 역량·기술별 근거 항목, 이력서 문장, 지표(범위와 출처 포함), 결정과 결정 주체, 교훈, 열린 질문
- [entries.jsonl](dev-log/entries.jsonl): 한 줄에 업데이트 하나. 배경, 문제, 검토한 대안과 이유, 한 일, 결과, 트레이드오프, 예상 면접 질문까지 포함

- 기준일: 2026-10-17
- 저장소: https://github.com/ki0915/EvidScope (작업 브랜치 `claude/evidence-layer`)
- 상태: 개인 프로젝트, 로컬·폐쇄망 파일럿. 고객 운영 실적과 법률 인증은 없습니다.

---

## 1. 한 줄 소개

AI 코딩 에이전트(Claude Code, Codex)가 실제로 한 행동을 실시간으로 받아 위험을 탐지하고, 운영자도 몰래 바꿀 수 없는 서명 원장에 남겨 ISMS-P·인공지능기본법·EU AI Act 검토 증거로 쓰게 하는 AI 거버넌스·보안 감사 도구.

## 2. 세 문단 소개

**문제.** 회사 안에서 AI 에이전트가 명령을 실행하고 파일을 읽고 외부로 데이터를 보내지만, 무엇을 했는지·그때 권한이 있었는지·기록이 나중에 바뀌지 않았는지를 사람이 확인할 수단이 부족합니다. 에이전트 기록에는 명령, 경로, 비밀값 같은 민감 정보가 들어 있어 외부 AI 서비스로 분석을 보내기도 어렵습니다.

**해결.** EvidScope는 에이전트의 도구 호출을 hook으로 받아 위험 규칙 67개와 행동 순서 규칙으로 실시간 경보를 내고, 확실한 위험(감사 도구 무력화, 보안 기능 끄기, 비밀 즉시 전송)은 실행 전에 막습니다. 모든 기록은 Merkle 트리와 독립 위트니스 공동서명으로 되돌리기·삭제를 탐지하는 원장에 남고, 감사인은 운영자를 믿지 않고도 오프라인에서 다시 검증합니다. 규칙이 잘못 울린 경보는 로컬에서 도는 판정 모델 두 개가 교차 검증해 낮추고, 관련 법·인증 항목은 서명된 대응표가 계산합니다.

**과정.** 처음에는 보안 때문에 PC 안에서 도는 보안 특화 모델(Foundation-Sec 8B)을 학습했지만, 처음 보는 위협 유형에서 위협을 놓쳤고 위협 탐지는 정적 규칙을 넘지 못했습니다. 스스로 낸 만점은 적대적 감사로 데이터 누수였음을 밝혀 무효화했습니다. 그 뒤 GPU를 빌려(합성·공개 데이터만 외부로) Qwen3-4B와 JEV-9B를 같은 답안지로 학습하고 역할을 나눠, 설계한 위협 유형의 처음 보는 세션에서 정확도 약 70%(규칙만)를 답한 것 기준 100%로 끌어올렸습니다.

## 3. 대상 사용자

- 기업 내부감사, AI 거버넌스 담당자, 보안 운영팀(SOC)
- 사내망·VPC 안에서 AI 에이전트 사용을 감사해야 하는 조직 (목표 배포 환경)
- 첫 시연 대상: 오너 PC의 실제 Claude Code·Codex 사용 기록

## 4. 개발 방식과 기여 구분

- 1인 프로젝트 오너가 문제 정의, 우선순위, 보안·비용·모델 조건, 방향 전환, 결과 검토와 공개 판단을 맡았습니다.
- 설계·구현·적대적 감사는 역할을 나눈 AI 코딩 에이전트와 협업했습니다. 감사 역할은 구현 역할과 분리해 "만든 쪽이 스스로를 공격"하도록 했습니다.
- 오너가 내린 대표 결정: 데이터가 PC 밖으로 나가지 않는 로컬 모델 우선, 추가 API 비용 0원, "학습보다 수집·탐지 먼저"로 방향 전환(10-15), 적대적 감사 요청(10-17), 실패한 모델 퇴역, GPU 임대와 두 모델 동시 학습, "확실한 것만 차단", 목표 정확도 99%, Datadog/Grafana풍 콘솔 요청.

## 5. 시스템 구조

```
AI 에이전트(Claude Code·Codex)
  └ hook: 실행 전·후 기록(행위자, 도구, 대상, 목적지, 권한 모드), 도구 결과는 라벨·개수·해시만
      └ [실행 전 차단] 확실한 위험만 거부, 나머지는 경보
ingress(수집, OTLP/HTTP 포함) → vault(서명 원장, 암호화 저장, 평가 엔진 v9)
  ├ 위험 규칙 67개 + 행동 순서 규칙 → 경보
  ├ 서명된 대응표 v5 → ISMS-P·인공지능기본법·EU AI Act 항목
  ├ 투명성 로그(C2SP 체크포인트) → 독립 위트니스 공동서명
  └ 내보내기: 감사인용 증빙 묶음(DSSE·in-toto), OCSF → SIEM
판정 오케스트라(학습 완료, PC 배포 예정)
  규칙 → JEV-9B(모든 세션 1차 판정) → Qwen3-4B(걸린 세션의 증거 행동·유형) → 서명된 표가 조항 계산
운영 콘솔: 대시보드, 로그 탐색(facet·히스토그램·live tail), 경보, 조사, 거버넌스, AI 검토실
```

## 8. 대표 에피소드 (STAR)

### E1. 보안 때문에 고른 로컬 모델이 실패했고, 판정 오케스트라로 다시 설계했다
- **상황:** 감사 대상인 에이전트 기록에는 명령·경로·비밀값이 들어 있어 외부 AI API로 보낼 수 없었다. 추가 API 비용도 0원이 조건이었다.
- **과제:** PC 안에서 돌면서, 처음 보는 위협 유형에서도 규칙의 오경보를 줄이고 위협은 하나도 놓치지 않는 판정 모델.
- **행동:**
  1. 보안 특화 Foundation-Sec 8B를 RTX 3080 12GB에서 QLoRA로 학습했다. 증거 문장 → 규제 항목 매핑 파일럿 13번, 세션 판정 3번을 한 번에 하나씩 바꾸며 시도했다.
  2. 실패 원인을 숫자로 좁혔다. 처음 보는 유형에서 위협을 놓쳤고(탐침 13개 중 9개, 규칙은 13개 모두), 확신도가 0.9로 고정돼 보류를 못 했고, 규칙 소견을 빼면 유출을 정상으로 판정했다. 모델을 근거와 함께 퇴역시켰다.
  3. 구조부터 바꿨다. 법 조항은 서명된 대응표가 계산하고, 모델은 규칙 경보를 지울 수 없고 낮추려면 두 모델이 동의해야 한다.
  4. 12GB 한 장으로는 두 모델을 동시에 학습할 수 없어 vast.ai GPU를 빌렸다. 실제 수집 기록은 PC에 두고 합성 시나리오와 공개 데이터만 보냈다.
  5. Qwen3-4B와 JEV-9B를 같은 답안지로 학습했다. 같은 경보에 정답이 다른 대조 쌍, 경보 이름 가림·규칙 출력 제거 변형, 외부 시험(R-Judge) 분리, 검증 분할로만 고르는 보류 문턱을 썼다.
  6. 측정된 강점으로 역할을 나눴다. JEV-9B는 글을 생성하지 않고 판정 블록이 확률을 바로 내므로 모든 세션의 1차 판정을 맡는다. Qwen3-4B는 규칙 경보 없이도 증거 행동을 짚으므로(증거 단계 F1 0.86, JEV 0) 걸린 세션만 맡는다.
- **결과:** 규칙만 약 70% → JEV-9B 처음 보는 세션 모두 정답, 교차 검증 99.4% 답변·100% 정답(4회차 1,050건 모두 정답), 외부 시험 63% → 87%. 크레딧 $5 안에서 5회차.

### E2. 스스로 낸 "만점"을 적대적 감사로 무효화했다
- **상황:** 첫 세션 판정 학습이 처음 보는 60세션에서 모든 지표 1.0을 냈다.
- **과제:** 결과가 진짜인지 확인.
- **행동:** 학습·채점 전 과정을 공격자 시각으로 다시 쟀다. 평가용 패턴이 학습 360세션 중 96개에 섞여 있었고, 정답이 경보 코드 조합만으로 정해져 모델 없는 "경보 코드 4개 무시" 한 줄 규칙도 1.0을 냈다. 확신도는 정답에 넣은 고정값 0.9/0.1을 그대로 따라 했다.
- **결과:** 1.0을 무효로 되돌리고, 누수 검사 4종(걸리면 학습 세트를 만들지 않음), 모델 없는 기준선, 대조 문제, "모델은 경보를 지울 수 없다"는 처리 원칙을 코드로 넣었다. 이후 모든 회차가 이 장치를 거쳤다.

### E3. "99%"를 통계로 정의하고 시험을 다시 설계했다
- **상황:** 오너 목표는 정확도 99%였는데, 매핑 파일럿의 99% 운영점은 25/25였다.
- **행동:** 25/25의 95% 신뢰 하한이 약 88%라는 것을 보이고, 99%를 "답한 것의 정밀도 + 나머지는 규칙·사람에게 보류"로 정의했다. 오류 0으로 99%를 말하려면 약 300건이 필요해 시험을 350세션 × 3변형으로 키웠다.
- **결과:** 2회차부터 350세션 오류 0으로 95% 하한 약 99.1%를 근거로 말할 수 있게 됐다. 동시에 "설계한 위협 유형 안에서만"이라는 범위를 분명히 했다.

### E4. 운영자를 믿지 않아도 되는 증거 계층
- **상황:** 적대적 감사에서 원장 전체를 지우거나 옛 사본으로 되돌려도 탐지되지 않았다(S1). 서명키 하나로 모든 문서·백업이 복호화됐다(S2).
- **행동:** 제품을 "SIEM"에서 "AI 행동 증거 계층"으로 재정의하고, tenant별 RFC 6962 Merkle 트리와 C2SP 체크포인트를 독립 위트니스가 공동서명하게 했다. 키를 HKDF로 분리하고 이벤트 키를 epoch KEK로 감싸 파기가 백업까지 미치게 했다. 위트니스 서버는 직접 만들지 않고 기존 구현(litewitness)과 상호운용 시험을 했다.
- **결과:** 롤백·포크·tenant 삭제를 거부하거나 격리하고, 검증 결과에 보증 수준(`database_tamper`, `signing_key_holder`, `vault_host`)을 표시한다.

### E5. 측정으로 찾은 병목, 보장을 지키며 처리량 약 4배
- **행동:** `--cpu-prof`로 vault 단일 스레드가 이벤트마다 트랜잭션·fsync·체크포인트 검증을 반복하는 것을 찾았다. 응답을 영속 전에 보내거나 fsync를 완화하는 방법은 버리고, group commit, 검증 캐시, SAVEPOINT 제거, tenant 분할을 차례로 적용했다.
- **결과:** 버스트 262 → 1,075 EPS, OTLP 759 → 1,868 EPS. 단일 tenant 목표(2,000 EPS) 미달도 공개했다.

### E6. 실제 AI 에이전트 실시간 감시와 최소 차단
- **상황:** 오너가 "위협도 감사도 아무것도 안 되는 거 아니야?"라고 물었다. 실제로 PC의 어떤 AI 도구도 기록을 보내지 않았다.
- **행동:** 모델 학습을 뒤로 미루고 Claude Code·Codex hook을 붙였다. hook은 절대 작업을 막거나 망가뜨리지 않고(기본), EvidScope가 꺼져 있으면 대기열에 둔다. 행동 순서 규칙(민감 파일 읽기 → 30분 안에 외부 전송 등), 정규식 없는 단어 순서 연산자, 원문 없이 라벨·개수·해시만 보내는 LLM 보안 신호를 더했다. 차단은 오너가 고른 "확실한 것만" 수준으로 설계했다. 이어서 "누구 에이전트이고 누가 책임지나"라는 지적에 기록마다 실행자(계정·PC·저장소·git 사용자)를 싣고, 새 에이전트 자동 등록과 매핑 표 기반 책임자 추정을 만들었다. 책임자 확정은 검토자의 서명 기록으로만 남는다(AM-14). "모든 LLM 활동 로그를 무결하게"라는 요구에는 hook 기록마다 순번과 앞 기록 해시를 붙여, PC에서 금고까지 오는 사이의 유실·변경·중복을 서명된 수집 공백 경보로 남기게 했다(AM-15).
- **결과:** 실제 미끼 시연에서 순서 경보(high) 발생, 실제 기록 1,767건 새 오탐 0, 지난 행동 6,237건 소급 수집, 설치된 hook에서 차단 확인.

### E7. 피드백을 바로 화면으로: 다크 운영 콘솔
- **상황:** "UI가 별로", "DataDog이랑 Grafana 참고", "참고 내용을 알 수 없다", 로그 검색·분류 필요.
- **행동:** 대시보드, facet 8종과 검색 문법, 히스토그램 클릭 확대, 2초 live tail, 행동마다 "같은 세션에서 먼저 읽은 자료"를 보여 주는 콘솔을 만들었다. 기존 화면 수십 개는 밝은 스타일에서 어두운 짝을 자동으로 만드는 스크립트로 옮겼다. 경보의 관련 법·인증 기준은 기준별 한 줄 번호로 압축하고, 데모 경보 63건은 원장을 건드리지 않고 보기 분류로 분리했다.
- **결과:** 경보 1건 표시 약 20줄 → 1줄, 보존 화면 응답 913 → 103KB, 시험 실패 0, PC 29개 파일 해시 확인 후 반영.

### E8. 출시 직후 발견한 권한 상승을 회귀 시험으로 닫았다
- **행동:** 읽기 전용이어야 할 감사자 계정이 거버넌스 데이터를 바꿀 수 있던 결함을 서버 쪽 역할 검사로 막고, 실제 HTTP 거부 30건에서 서명 상태가 바뀌지 않음을 회귀 시험으로 고정했다.
- **결과:** v0.1.1 설치본 10회 반복 390/390.

### E9. 외부 오탐의 원인을 데이터에서 찾고, 어떤 모델에도 쓸 수 있는 데이터셋으로 바꿨다
- **상황:** JEV의 외부 시험(R-Judge) 안전 세션 오탐이 4회차 43건에서 7회차 153건(269건 중)으로 늘었다. 우리 시험에서는 98~100%였다.
- **행동:** 학습 없이 할 수 있는 것부터 시험했다. 여러 회차 앙상블은 오탐 집합이 서로 포함 관계라 거의 효과가 없었고(가장 좋은 짝 35건), 외부용 문턱은 R-Judge를 올리는 대신 다른 공개 시험을 0.887에서 0.744로 떨어뜨렸다. 같은 데이터로 다시 학습해 우연의 폭(오탐 77 → 116건)을 쟀다. 그리고 오탐을 기록 종류별로 나눠 81~93%가 "공격 문구가 들어왔지만 에이전트가 따르지 않은 정상 세션"임을 찾았다. 오너가 "어떤 모델이 나와도 학습·조정할 수 있는 데이터셋"이 가장 중요하다고 해, 그 신호가 있는 공개 데이터셋을 R-Judge 원천 계열을 빼고 받고(겹침 0), 모든 세션을 프롬프트 없는 한 레코드 형식으로 모았다. 지금 모델이 학습하는 행과 바이트까지 같음을 테스트로 보장했고, 주입 환경 하나에서 "무시한 정상"과 "따른 위반" 두 세션을 구성 라벨로 만들었다.
- **결과:** 진행 중이다. 새 데이터로 학습한 회차의 결과를 기다린다(JM-26, JM-27).

## 9. 결정과 이유

| 고민 | 선택 | 이유 |
|---|---|---|
| 외부 AI API vs 로컬 모델 | 로컬 | 에이전트 기록의 민감 정보, 추가 비용 0원, 사내망 배포 목표 |
| 학습을 PC에서만 vs 임대 GPU | 임대 GPU, 합성·공개 데이터만 | 12GB로 두 모델 동시 학습 불가, 실제 기록은 PC에 남김 |
| 한 모델에 다 맡기기 vs 역할 분담 | 규칙·판정 모델 2개·정책 모델·서명 표로 분담 | 한 모델 의존이 반복 실패, 틀리면 안 되는 일은 코드로 |
| 모델이 법 조항을 직접 출력 vs 표가 계산 | 서명된 대응표가 계산 | 모델이 조항을 틀리게 쓸 수 없고 재현 가능 |
| 모델이 경보를 지울 수 있게 vs 낮추기만 | 낮추기만, 보호 경보는 그대로, 두 모델 동의 필요 | 학습 모델이 기록 변조 탐지를 지운 사고 |
| 차단 수준 | 확실한 것만 차단, 나머지는 경보 | 오차단은 개발을 멈춤, 막은 사실은 원장에 남김 |
| 실시간 보기 방식 | 기존 인증 API 폴링(켰을 때만) | 새 연결 방식 없이 구현(추정, 문서화되지 않음) |
| 자체 trace 화면 vs 기존 도구 | Langfuse·Phoenix에 검증 결과를 얹음 | 관측 화면은 이미 성숙, 차별점은 오프라인 검증 |

## 10. 배운 점

- 만점과 "모두 통과"는 먼저 의심하고, 모델 없는 단순 기준선과 비교해야 한다.
- 라벨이 지름길을 허용하면 모델은 지름길을 배운다. 대조 쌍과 변형 시험이 그것을 깬다.
- 확신도는 모델의 말이 아니라 확률로 재고, 문턱은 시험과 같은 분포의 검증 분할로 고른다.
- 작은 시험의 만점은 통계적으로 약하다. 목표 정확도에 맞춰 시험 규모부터 설계한다.
- 외부 시험은 따로 지키고, 겹치는 공개 데이터는 학습에서 기계적으로 뺀다.
- 데이터 경계를 먼저 정하면 외부 자원을 써도 원칙을 깨지 않는다.
- 감사 제품에서는 "모른다"를 상태로 드러내는 것이 신뢰를 만든다.

## 11. 한계와 진행 중 (과장하지 않기 위해)

- 99%는 **설계한 위협 유형** 안의 결과다. 다른 종류 에이전트(R-Judge)는 JEV가 회차에 따라 68~87%(최고 4회차), Qwen이 57~70%(안전 세션 대부분을 위험으로 봄)다. 같은 데이터로 다시 학습해도 오탐이 77건에서 116건으로 흔들려, 한 번의 비교로는 약 40건 차이까지 우연일 수 있다.
- 판정 모델은 **아직 PC에 배포하지 않았다.** 실제 세션에서의 속도·메모리·오탐률은 미측정이다.
- JEV-9B는 Qwen3-4B보다 **큰 모델**이다(학습 최대 메모리 7.4GB vs 3.7GB, 세션당 0.31초 vs 0.38초). "경량 모델"이라고 쓰지 않는다. 비용·속도 이점은 Qwen을 걸린 세션에만 부르는 구조에서 나오며, 실제 절감률은 배포 후 측정한다.
- 판정 이유를 문장으로 쓰는 기능은 아직 없다(Qwen은 증거 행동과 위험 유형을 답한다).
- 학습·평가 라벨은 설계로 만든 합성 데이터와 공개 데이터다. 사람이 검토한 라벨은 없다.
- 고객 운영 실적, 법률 준수 인증, 실제 금융기관 연동은 없다. 대응표는 "검토할 때 볼 증거 위치"이지 준수 판정이 아니다.

# EvidScope 기능과 비용 설계

EvidScope는 에이전트의 행동·참고자료·권한·결과를 연결해 사람이 판단하도록 돕는 로컬 감사 지원 파일럿이다. 개발팀의 에이전트 협업을 관측하는 기능과, 서비스에서 로컬 AI가 검토 초안을 작성하는 기능을 함께 제공한다. 현재는 사람이 사건과 역할을 선택해 실행한다. 모든 운영 역할을 자율적으로 순서 배정하거나 중요 사건을 고급 모델에 자동 전송하는 기능은 아직 구현하지 않았다.

## 두 종류의 에이전트 팀

| 구분 | 구성 | 현재 실제 동작 |
|---|---|---|
| 제품 개발팀 | Astra 설계·검토, Sol 핵심 구현, Claude UI | 역할별 작업 명세와 worktree, 인수인계, 별도 감사. 등록 작업의 동시 실행 상한은 coordinator 포함 3개 |
| 서비스 운영 역할 | 증거 정리, 근거 대조, 거버넌스 지원, 보고서 초안 | 공통 로컬 모델(`fdtn-ai/Foundation-Sec-1.1-8B-Instruct`, 공개 기본 모델 그대로)에 역할별 지침·지식·출력 계약 적용. 사용자가 사건 하나와 역할 하나를 선택해 실행. 처음 배포한 Qwen3 4B 정책은 테넌트 프로필 첫 조회 때 새 버전으로 바뀐다 |

개발용 고급 모델이 서비스를 계속 분석하는 구조는 아니다. Codex와 Claude 실행 이벤트는 내용·내부 사고 과정을 제외한 허용 메타데이터로 수집한다. 운영용 모델도 테스트나 명시적 사건 분석 때만 실행하고, 시험 종료 후 중지한다.

## 지금 사용할 수 있는 기능

1. **행동 조사:** AI 자기보고와 도구 실행 결과, 승인·권한 기록, 참고자료 ID·버전·해시를 대조한다. 성공 보고와 실패 결과처럼 서로 다른 출처의 기록을 함께 보여 준다.
2. **에이전트 목록과 시간축:** 에이전트별 관측 정책 준수율, 평가 범위, 미확인·재검토 현황을 조회한다. 주식형 시간축의 확대·이동·최신 따라가기와 목적별 집계를 지원한다.
3. **개발팀 실행 관측:** 팀·역할·실행·부모 관계·도구 메타데이터·실패·사용량을 기록한다. 관측되지 않은 부모나 모델 정보는 확인된 것처럼 채우지 않는다.
4. **로컬 AI 검토:** 사람이 선별한 사건 자료를 고정하고, 실행 하나에 한정된 자격으로 모델에 전달한다. 네 역할의 지침과 출력 계약이 실제 실행 묶음에 들어간다.
5. **기계 초안과 사람 판단 분리:** 초안의 채택·수정·반려 기록은 기존 사건 판단이나 정책 점수를 덮어쓰지 않는다. 새로운 사건·증거·규정 문맥이 생기면 최신성 확인이 필요하다.
6. **첫 화면과 실행 중 에이전트:** 로그인하면 `지금 확인할 일` 화면이 먼저 열린다. 최근 기간에 기록이 들어온 에이전트, 위협 신호, 사람의 검토를 기다리는 항목, 프레임워크별 증거 유무를 한 화면에 모은다. 아래 [첫 화면](#첫-화면-지금-확인할-일)을 참고한다.
7. **최근 기록 우선 목록:** 이벤트·발견 사항·사건 목록은 기본으로 최근 기간만 보여 주고, `이전 기록 더 보기`로 과거를 이어 읽는다. 아무 기록도 지우지 않는다.
8. **평가와 학습 준비:** 역할별 60개, 총 240개의 합성 사례와 구조화된 검사기를 제공한다. 모두 `UNREVIEWED`이며 학습 완료나 검증된 정답 자료로 취급하지 않는다.

```mermaid
flowchart LR
  E[관측 이벤트] --> R[규칙 기반 대조]
  R --> H[사람이 사건과 근거 선택]
  H --> L[선택한 로컬 전문 역할]
  L --> V[출력 형식과 인용 범위 검사]
  V --> D[AI 초안]
  D --> J[사람의 채택 수정 반려]
```

이 그림은 현재 실행 흐름이다. 역할들이 서로 작업을 자동 위임하는 팀 실행기로 해석하지 않는다.

## 첫 화면: 지금 확인할 일

왼쪽 메뉴 `현황 → 지금 확인할 일`(`#home`)이 기본 화면이다. 세 열로 나뉘고, 좁은 화면에서는 한 열로 접힌다. 모든 수치는 볼트에 이미 있는 기록에서 계산하며, 화면을 여는 일은 원장에 접근 기록(`audit_access_batch`)만 남긴다. 숫자를 누르면 같은 조건으로 걸러진 목록이 열린다.

| 열 | 보여 주는 것 | 누르면 열리는 곳 |
|---|---|---|
| 위협 | 미해결 발견 사항(심각도별, 마지막 방문 이후 새로 생긴 수), 보류되지 않았거나 전파가 확인되지 않은 정지 명령, 무결성 경보(격리·검증 실패) | 발견 사항 목록(심각도·미해결 필터), 정지 명령, 무결성 상태 |
| 검토 대기 | 남은 시간이 표시된 승인 요청, 검토를 기다리는 사건, 두 번째 승인자를 기다리는 등록 변경과 정지 해제, 열린 거버넌스 과제와 법률 검토 대기 | 승인함, 사건 목록(상태 필터), 에이전트 등록부, 거버넌스 과제 |
| 거버넌스 지원 | 프레임워크별(EU AI Act 기록 의무, 인공지능 기본법, ISMS-P) 매핑 항목 가운데 기간 안에 `증거 있음` / `기록 없음` / `여기서 세지 않음` 수. 기간은 7일·30일·90일 | 항목 목록과 감사 패키지 만들기 명령 |

- **마지막 방문 이후:** 같은 브라우저에서 같은 사용자가 마지막으로 첫 화면을 연 시각을 기억해 그 뒤에 생긴 발견 사항을 따로 센다. 이 기억은 브라우저에만 남고 서버로 보내지 않는다.
- **역할에 따른 차이:** 감사인(auditor)은 모든 수치를 읽지만 `내가 답할 수 있음` 수치는 0이다. 검토자·관리자는 자신이 등록·요청한 항목을 제외한(4-eyes) 수를 본다.
- **증거 있음은 준수가 아니다:** 거버넌스 지원 열은 증거 패키지 매핑(`src/evidence-pack-frameworks.mjs`)과 같은 규칙으로 기간 안에 해당 종류의 기록이 있는지만 센다. 요구사항 충족이나 법적 준수 판정이 아니며, 화면도 `준수`라는 말을 쓰지 않는다. API 응답·저장소 파일·온라인 점검처럼 원장 밖에서 확인해야 하는 근거는 `여기서 세지 않음`으로 따로 표시한다.
- **감사 패키지:** `감사 패키지 만들기`는 기간·테넌트·프레임워크가 채워진 `node scripts/evidence-pack.mjs build` 명령을 보여 준다. 패키지 서명은 서버 화면이 아니라 운영자가 CLI에서 만든다.
- **모델 현황 요약:** 첫 화면 아래에 검토 모델 이름, 미세조정 어댑터 부착 여부, 학습 기록 수를 한 줄로 보여 주고 `모델 현황`으로 연결한다.

### 실행 중 에이전트

`현황 → 실행 중 에이전트`(`#agents-now`)는 선택한 기간(5분·15분·1시간·24시간, 기본 15분) 안에 기록이 들어온 에이전트를 최근 활동 순으로 보여 준다. 30초마다 다시 읽는다.

- **활동의 뜻:** 기간 안에 그 에이전트의 기록이 볼트에 수신됐다는 뜻(`receivedAt` 기준)이다. 생존 신호(heartbeat)가 아니다. 기록이 없다고 멈춘 것이 아니고, 기록이 있다고 지금 실행 중이라는 뜻도 아니다.
- **등록·미등록:** 등록부 항목은 출처 자격과 행위자 이름으로 묶는다. 등록되지 않은 출처·행위자는 `미등록` 표시와 함께 따로 묶이며, 미등록 행위자 이름은 출처의 자기 보고다. 행위자 이름이 없는 도구·집행 기록은 에이전트에 붙이지 않고 `에이전트에 붙지 않은 기록` 수로만 센다.
- **한 줄에 보이는 것:** 마지막 활동 시각, 기간 안의 이벤트·행동·결정·거부 수, 등록부 상태, 활성 정지 명령, 대기 중 승인, 미해결 발견 사항.
- **경고 표시:** `정지 명령 이후 활동`, `정지 상태에서 활동`, `폐기 후 활동`, `미등록 에이전트`.
- **기록 없는 운영 에이전트:** 운영·승인 상태인데 기간 안에 기록이 없는 등록 에이전트를 아래 표로 따로 보여 준다. 마지막 기록 시각은 출처 자격 기준이다.
- **비용 한도:** `events(tenant, received)` 색인 범위 하나를 최신순으로 읽고, 최대 20,000건·32MiB에서 자른다. 잘리면 수치가 하한이라고 표시한다. 사건 10만 건(30일 분산) 테넌트에서 측정한 응답 시간은 15분 약 3~4ms, 1시간 약 4~7ms, 24시간(3,331건) 약 35ms였다.

### 최근 기록 우선 목록

`이벤트`, `발견 사항`, `사건` 목록은 기간 선택(1시간·24시간·7일·30일·전체)을 가진다. 기본은 이벤트·발견 사항 24시간, 사건 30일이며 발견 사항은 `미해결`이 기본이다. 목록 위에는 기간 안의 전체 수를, 아래에는 `이전 기록 더 보기`를 둔다. 서버는 `since`·`until`·`cursor`·`order=desc` 매개변수로 최신순 페이지를 돌려주고 `windowTotal`, `hasMore`, `nextCursor`를 함께 보낸다. 이 매개변수를 쓰지 않는 기존 API 호출의 응답은 그대로다. 오래된 기록은 숨겨질 뿐 삭제되지 않는다.

### 모델 현황

AI 검토실의 `모델 현황` 탭(`#assistance-model`, `GET /api/model-status`)은 읽기 전용이다.

- 역할별 모델과 리비전, 모델 실행 환경 사용 여부, 역할 패키지의 평가 상태(`UNREVIEWED` 등)를 보여 준다.
- **미세조정 어댑터:** 현재 어떤 역할에도 붙어 있지 않다. 검토 모델은 공개된 기본 모델 그대로다.
- **이전 정책이 남은 테넌트:** 서명된 프로필이 아직 1판(Qwen3 4B)이면 `이전 기본값 … → … 자동 갱신 예정`으로 표시한다. 그 모델로 실행된다는 뜻이 아니다. 실행은 현재 정책만 허용하며, AI 검토실을 처음 열 때 새 판이 서명된다.
- **서명된 팩트시트:** 거버넌스 매핑 모델의 학습·평가·승격 실행마다 운영자가 기록한 팩트시트(볼트 원장 객체)를 보여 준다. 셰이크다운 실행은
  `셰이크다운 — 승격 불가, 품질 결과 아님`으로 표시하고 자원 수치만 보여 준다([거버넌스 매핑 로컬 모델](governance-model.md)).
- **학습 기록:** 저장소 기록(`data/training-runs.json`)에 있는 실행은 실행 ID·기본 모델·데이터셋·점수와 항상 유보 기준선 비교·승격 여부로 보여 준다. 현재 기록 하나는 128문항 중 60개 통과로, 모든 질문에 유보하는 기준(64개)보다 낮아 승격하지 않았다. 기록이 없으면 `학습 기록 없음`과 학습 실행 방법(`scripts/training-run.mjs`)을 보여 준다.
- **승격은 자동이 아니다:** 사람의 승인 파일과 비교 평가 보고서가 있어야 `scripts/model-promote.mjs`로 승격할 수 있다. 이 화면은 학습이나 승격을 시작하지 않는다.
- 데이터 출처는 서버 함수 하나(`src/model-status.mjs`)에 모여 있어 이후 다른 상태 원천으로 바꿀 수 있다.

### 학습 데이터 검토와 실험 비교

AI 검토실의 `학습 데이터 검토` 탭(`#model-review`)은 Claude가 쓴 거버넌스 매핑 학습 데이터 초안을 한 행씩 보여 주고, 검토자·관리자가
승인 또는 거절한다(단축키 A·R·N·P). 결정은 서명된 원장 기록이고, 학습 파일은 `governance-mapping.mjs export-reviewed`가 감사 내보내기
파일에서 만든다. `실험 비교` 탭(`#model-experiments`)은 저장소의 비교 보고서를 기준선·기본 모델·어댑터 후보별로 나란히 보여 주고 실행 이력과
팩트시트 기록 양식을 둔다. 자세한 규칙은 [거버넌스 매핑 로컬 모델](governance-model.md)에 있다.

## 검증 에이전트와 검사기의 역할

개발팀에는 구현 문맥과 분리된 고급 모델 감사 역할이 있다. 첫 Astra 감사는 별도 재현 검사로 결함을 보고했다. 이후 수정에 대한 독립 재감사 완료 여부는 최신 시험 보고서에서 따로 확인한다.

서비스의 `근거 대조` 역할은 자료 사이의 일치·불일치·미확인을 정리한다. 다만 다른 역할의 출력을 자동으로 받아 독립 승인하는 검증 에이전트로 연결되지는 않았다. 현재 코드 검사는 출력 구조, 인용의 소속 범위, 버전·해시, 작업 자격과 상태를 확인한다. 인용 ID가 존재한다는 사실만으로 주장의 의미적 타당성을 증명하지 못한다. 실제 Qwen 시험에서 이 차이가 드러났고 해당 초안은 시험상 반려했다.

## 비용을 줄이는 목표 구조

작업 난도와 영향도에 따라 필요한 계산만 사용한다. 모델이 표시한 자신감만으로 고급 검토 여부를 결정하지 않고 근거 충돌·권한 문제·자료 부족·사건 영향도를 함께 확인한다.

| 단계 | 담당 | 맡길 일 | 현재 상태 |
|---|---|---|---|
| 1 상시 관측과 정형 검사 | 코드와 규칙 | 수집·중복·권한·버전·형식·정책 대조 | 구현 |
| 2 일반 자료 정리 | 로컬 경량 모델의 전문 역할 | 출처 정리, 주장 대조, 누락 표시, 보고서 초안 | 단일 역할 실행 구현 |
| 3 중요 사건 선별 | 규칙과 인간 검토 | 고위험 신호, 근거 충돌, 법적 적용성 미확인, 유보·반복 실패 | 사람이 사건을 선택하는 단계. 자동 선별 큐는 후속 구현 |
| 4 정밀 검토 | 고급 모델의 별도 검토 세션 | 복합 원인 분석, 반례 검토, 중요한 설계·감사 | 개발 감사에서 사용. 운영 사건 자동 호출은 비활성 |
| 5 최종 판단 | 지정된 사람 | 자료 충분성, 적용성, 채택·수정·반려와 후속 과제 | 인간 검토 흐름 구현 |

```mermaid
flowchart LR
  A[규칙과 코드] --> B[로컬 전문 역할]
  B --> C{중요 검토 대상인가}
  C -->|일반 사건| D[일반 검토함]
  C -->|근거 충돌 영향도 미확인| E[고급 검토 후보]
  E --> F[사람의 범위 확인과 비식별]
  F --> G[구독 도구에서 고급 모델 검토]
  G --> H[출처가 있는 검토 의견]
  D --> I[사람의 최종 판단]
  H --> I
```

이 그림은 발전 목표다. 자동 선별 큐, 운영 역할의 순차 팀 실행, 고급 검토 결과의 자동 가져오기는 아직 구현 완료 기능이 아니다.

추가 API 예산은 **0원**으로 시작한다. 고급 검토는 사람이 확인한 최소 자료를 기존 구독 도구로 전달하는 절차로 운영한다. 서비스가 유료 API로 자동 전환하거나 구독 세션을 무단으로 재사용하지 않는다. 구독 한도 소진 시 대기하고 크레딧·GPU 임대로 넘어가지 않는다. 로컬 전력, 보유 장비, 기존 구독료와 사람의 검수 시간은 별도 비용이다.

가격 경쟁력은 앞으로 동일한 사건군에서 `전체 사건 수`, `로컬 처리 수`, `고급 검토 수`, `재작업 횟수`, `확인 가능한 사용량`, `사람의 수정 시간`을 함께 측정해 판단한다. 아직 고급 호출 감소율이나 비용 절감률을 실측했다고 주장하지 않는다. 미확인 사용량은 0으로 환산하지 않는다.

## 전문화는 단순한 모델 이름 변경과 다르다

각 역할은 `roles/<역할>/v1`에 목적·지침·허용 도구 선언·지식 범위·출력 계약·유보 조건·평가 세트를 가진다. 실제 실행 묶음에는 이 역할 내용과 해시가 고정된다. 선언된 도구 이름은 실행 권한을 부여하지 않으며 현재 모델은 업무 도구를 실행하지 않는다.

LoRA는 사람 검수 학습 300개·검증 50개·시험 100개 등의 진입 조건을 충족한 뒤 증거 정리 역할부터 검토한다. 현재 인간 검수 수는 0개로 학습 진입이 차단돼 있다. 합성 시험 통과, 지침 조정, 가중치 학습, 실무 품질 승인은 별도 상태다.

## 포트폴리오 소개: 로컬 모델의 실패에서 판정 오케스트라까지

EvidScope는 AI 코딩 에이전트가 실제로 한 행동을 실시간으로 받아 위험을 탐지하고, 운영자도 몰래 바꿀 수 없는 서명 원장에 남겨 ISMS-P·인공지능기본법·EU AI Act 검토 증거로 쓰게 하는 AI 거버넌스·보안 감사 도구입니다. 아래는 판정 모델을 만들며 부딪힌 문제와 푼 방법, 그리고 화면을 고쳐 온 과정입니다. 업데이트마다 무엇이 바뀌었고 어떤 문제를 어떻게 고민해 풀었는지는 [개발 기록](docs/dev-log/README.md)(항목 75개, 대안·결정 주체·지표 출처·면접 질문 포함)에, 다시 생각해 볼 질문은 [회고 노트](docs/dev-log/reflection.md)에, 이력서·면접 준비용 요약은 [포트폴리오 컨텍스트](docs/portfolio-context.ko.md)에 있습니다. 이력서 도구나 경력 분석 엔진은 같은 내용을 [career-profile.json](docs/dev-log/career-profile.json)과 [entries.jsonl](docs/dev-log/entries.jsonl)에서 구조화된 데이터로 읽을 수 있습니다.

### 1. 보안 때문에 로컬 모델을 골랐다

감사 대상인 에이전트 기록에는 명령, 파일 경로, 비밀값이 들어 있습니다. 외부 AI API로 보내면 감사 도구가 새 유출 경로가 됩니다. 그래서 기록이 PC 밖으로 나가지 않고 추가 API 비용도 0원인 로컬 모델을 택했습니다. 보안 특화 공개 모델(Foundation-Sec 8B)을 RTX 3080 12GB에서 QLoRA로 학습했습니다. ([판정 모델 기록](docs/dev-log/03-judge-models.md))

### 2. 기대에 못 미쳤다: 처음 보는 유형에서 무너졌고, 위협 탐지는 정적 규칙을 넘지 못했다

- 증거 문장을 규제 항목에 연결하는 파일럿 13번이 모두 승격 기준을 넘지 못했습니다(최고 보정 정밀도 0.958, 재현율 0.46). 초기에는 "가장 가까운 학습 예시를 베끼는" 단순 기준선이 학습 모델보다 높았습니다(47% 대 39%).
- 세션 판정 첫 학습은 처음 보는 60세션에서 1.0을 냈지만, 적대적 감사로 확인해 보니 평가 패턴이 학습에 섞인 누수였고 모델 없는 한 줄 규칙도 같은 점수를 냈습니다. 결과를 무효로 되돌렸습니다.
- 적대적 탐침 위협 13개 중 정적 규칙은 13개를 모두 잡았지만 학습 모델은 9개만 잡았고, 에이전트가 자기 기록 설정을 고친 세션 3개를 정상으로 지웠습니다.
- 마지막 시도(v2)는 오경보 정리에서 규칙보다 나았지만(판정 정밀도 0.92 대 0.66) 확신도가 늘 0.9로 고정돼 판단 보류가 작동하지 않았고, 규칙 소견을 빼면 유출을 정상으로 판정했습니다. 근거를 남기고 이 모델을 퇴역시켰습니다.

### 3. GPU를 빌려 두 판정 모델로 교차 검증했다

- 12GB 한 장으로는 두 모델을 같은 데이터로 동시에 학습할 수 없어 vast.ai에서 RTX 5060 Ti 16GB 2장을 빌렸습니다(시간당 약 $0.29, 크레딧 $5). 데이터 경계는 지켰습니다. 합성 시나리오와 공개 데이터만 외부로 나갔고, 실제 수집 세션 시험은 PC에서만 합니다.
- Qwen3-4B-Instruct와 판정 전용 모델 JEV-9B를 같은 답안지로 학습했습니다. 같은 경보에 정답이 다른 대조 쌍, 경보 이름을 가리거나 규칙 출력을 지운 변형, 공개 데이터 ASSEBench를 섞고, R-Judge는 외부 시험으로만 남겼습니다.
- 규칙 경보를 낮추려면 두 모델이 모두 동의해야 합니다. 두 모델이 동의할 때만 답하면 처음 보는 세션의 99.4%에 답하고 답한 것은 모두 맞았고(3회차), 4회차에서는 세 변형 1,050건 모두에 답하고 모두 맞았습니다.

### 4. 역할을 나눴다: JEV가 먼저 거르고, Qwen이 근거를 짚고, 조항은 코드가 계산한다

- **JEV-9B:** 글을 생성하지 않고 판정 블록이 예/아니오와 확률을 한 번에 냅니다. 처음 보는 세션 판정 정확도와 외부 일반화가 더 높아 모든 세션의 1차 판정을 맡습니다. 모델 크기는 Qwen3-4B보다 크고 세션당 시간은 비슷합니다(0.31초 대 0.38초). 비용과 응답 속도의 이점은 Qwen을 걸린 세션에만 부르는 구조에서 나옵니다.
- **Qwen3-4B:** 규칙 경보가 없어도 어느 행동이 증거인지 짚습니다(규칙 출력을 지운 시험에서 증거 단계 F1 0.86, JEV는 0). 그래서 JEV가 걸러낸 세션의 증거 행동과 위험 유형을 맡습니다.
- **코드:** 법 조항은 모델이 쓰지 않고 서명된 대응표가 계산합니다. 모델은 규칙 경보를 지울 수 없고, 방어 무력화·민감 접근 후 외부 전송·기록 변조 같은 보호 경보는 낮추지도 못합니다.

|---|---|---|---|---|
| 처음 보는 유형 세션 | 정확도 약 70% | 판정 정밀도 0.70 | 모두 답변, 모두 정답 (3회차 98.9% 답변) | 모두 답변, 모두 정답 |

## 목적과 대상

실행 로그만으로는 AI가 실제로 무엇을 했고, 당시 권한이 있었으며, 어떤 근거를 검토했는지 설명하기 어렵습니다. EvidScope는 **AI 행동 → 독립 도구 결과 → 당시 권한·정책 버전 → 원본 문서 → 사람 판단**을 연결하고 서로 대조합니다.

SIEM이나 실행을 승인·차단하는 엔진이 아닙니다(예외는 Claude Code hook에서 맥락과 무관하게 확실한 위험만 막는 선택 모드입니다). 상관분석·대량 검색은 기존 SIEM과 관측 도구에 맡기고, 이 제품은 "그 행동이 권한 안에서 일어났고 기록이 사후에 바뀌지 않았다"는 증거에 집중합니다. 내부감사, AI 거버넌스 담당자, 보안 운영팀이 근거를 확인하고 판단을 기록하는 도구입니다. 등록된 AI 자산, 실제로 받은 기록, 증거 커버리지를 분리해서 "등록됨"과 "확인됨"을 혼동하지 않도록 설계했습니다.

> 법률 준수 인증과 실제 금융기관 연동은 완료되지 않았습니다.

## 구조와 스택

```mermaid
flowchart LR
  S[수집 출처] -->|HMAC·nonce| I[ingress]
  I --> V[vault<br/>tenant·role 인증<br/>서명 원장·암호화 저장<br/>projection 검증]
  W[worker<br/>claim·lease·version] <--> V
  U[인간 검토 UI] --> A[audit] --> V
  V --> E[export] -->|별도 공개키·checkpoint·hash| X[독립 검증]
  O[OTel SDK·Collector] -->|OTLP/HTTP| I
  V -->|heads 체크포인트| T[독립 위트니스] -->|공동서명| V
  V -->|OCSF| SIEM[기존 SIEM]
```

![증거 흐름](docs/assets/evidence-flow.svg)

시스템은 ingress, audit, vault, worker 네 개 프로세스로 나뉩니다. 최종 인증과 원장은 vault가 소유하고, worker는 claim·lease·version 방식으로 분석합니다. 인간 검토 UI는 분석 경로와 분리되어 있습니다.

- **런타임**: Node.js 24.15.x ESM(`node:http`, `node:crypto`, `node:sqlite`), SQLite WAL, Vanilla JS/CSS
- **인증·무결성**: openid-client 6.8.8(OIDC), Ed25519 서명, HMAC/nonce 기반 출처 인증
- **배포**: Docker·Kubernetes 배포 도구
- **분석 방식**: 탐지와 차단, 조항 계산은 상시 LLM 없이 결정적 규칙과 서명된 표가 맡습니다. 판정 모델(JEV-9B, Qwen3-4B)은 규칙 오경보를 낮추는 2선이며, Python/PyTorch/Transformers/PEFT(QLoRA)로 학습합니다. 학습은 로컬 RTX 3080과 임대 GPU(vast.ai, 합성·공개 데이터만)에서 했고, 추론은 PC에서 돌릴 예정입니다.

## 구현 문제 해결

**1. 서명 원장 재검증 병목**

요청마다 전체 원장을 재검증하면서 처리 속도가 떨어졌습니다. 이를 다음과 같이 해결했습니다.

- transaction checkpoint batching을 도입했습니다.
- 검증된 checkpoint 이후의 새 suffix와 projection delta를 검증합니다.
- 변조가 감지되면 fail-closed로 처리합니다.
- 전체 export, integrity 검사, backup은 여전히 전체를 검증합니다.

2026-10-05 합성 로컬 시험에서 **1,000/1,000건**을 접수했고, sustained **600/600건·p95 206.81ms**, 최종 backlog 0을 기록했습니다. 시험 환경은 i7-12700F, 32GiB, Windows, SQLite WAL, writer 1개·worker 2개였습니다. 단일 시험 결과이며 운영 SLA가 아닙니다. [원본 벤치마크](reports/benchmark-2026-10-05T06-29-04-501Z.json).

**2. 감사자의 거버넌스 변경 권한**

reviewer·admin 권한 검사를 적용했습니다. 실제 HTTP 거부 30건에서 서명 상태가 바뀌지 않는지 회귀 시험으로 고정했습니다. 실제 인증과 독립 검증·복구가 이 프로젝트의 핵심 구현 사례입니다.

**3. 문서의 존재와 충분한 근거를 구분**

암호화한 실파일의 hash·복구 가능성과 모델·목적·정책 버전을 대조합니다. 문서 손상이나 버전 변경은 재검토로 이어지며, 근거가 부족한 과제는 종결을 거부합니다. [문제 → 구현 → 결과 상세](docs/product-overview.md#6-어떤-구현으로-어떤-문제를-해결했는가).

## 실행

Node.js **24.15.x**가 필요합니다. 최초 실행 시 로컬 자격·키·DB를 만들며 모델·GPU 학습은 시작하지 않습니다.

```powershell
git clone https://github.com/ki0915/EvidScope.git
cd EvidScope
npm ci --ignore-scripts --no-audit --no-fund
npm start
```

기본 감사 화면은 **http://127.0.0.1:8082**입니다. `.local/config.json`의 역할별 토큰을 화면에 입력합니다. auditor는 조회 전용 역할이 아닙니다. 역할은 다음과 같습니다.

| 역할 (로컬 계정) | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|
| auditor (`alpha-auditor`) | 조회, 사건 생성·의견·과제 기록, 사람 판단 기록, 예외 요청, 다른 사람이 연 사건의 종결 | 자신이 열거나 다시 연 사건의 종결, 예외·룰 승인, 거버넌스 시스템·평가·과제 변경 |
| reviewer (`alpha-reviewer`) | auditor 권한 + 거버넌스 변경·검토, 룰 작성·시험, 다른 사람이 작성한 룰·예외 승인, 다른 사람이 작성한 거버넌스 평가의 법률 검토 확인 | 자기 작성물(룰·예외)의 단독 승인, 자기 평가의 법률 검토 확인, 자기 평가가 포함된 거버넌스 과제 종결 |
| admin (`alpha-admin`) | reviewer 권한 + 검색 사본 재구축, 접근 관리 | 자기 작성물의 단독 승인·법률 검토 확인·과제 종결 |

예외 요청은 다른 reviewer 또는 admin이 승인하기 전에는 분석 결과에 영향을 주지 않습니다. 사건 종결, 예외 승인, 거버넌스 평가의 법률 검토 확인과 과제 종결처럼 결과를 확정하는 변경은 작성자와 다른 사람이 해야 합니다(4-eyes). 평가 작성자가 입력한 `legalReview`는 주장으로만 표시되고, 다른 reviewer·admin이 그 평가 내용(해시)에 확인을 기록해야 `legalStatus`가 `reviewed`가 됩니다. 작성자가 `reviewed`를 입력해도 법률 검토 과제는 열리고, 독립 확인 전에는 종결할 수 없습니다. 증거가 vault가 확인하지 않은 진술·외부 참조뿐이면 보고서에 `self_asserted`로 표시됩니다. vault는 공급사 서명을 검증하지 않으므로, 공급사 증빙 묶음은 실제 자료로 신고되고 평가 작성자가 아닌 사람이 출처를 확인한 경우에만 출처에 묶인 증거(`vault_retained_supplier_bundle`)로 셉니다. 자격 파일은 공개하거나 공유하지 않습니다.

별도 터미널에서 `npm run demo`를 실행하면 합성 사례가 추가됩니다. 데모는 OpenTelemetry GenAI span도 `/v1/traces`로 보내므로 AI 가시성 화면에 등록 자산·미등록 자산·허용 목적지 밖 호출이 나타납니다. Windows에서 IPv4 loopback 오류가 있다면 서버·데모 양쪽에 `$env:EVIDSCOPE_LOCAL_HOST='::1'`을 설정하고 **http://[::1]:8082**로 접속합니다. `Ctrl+C`로 실행기가 시작한 자식 프로세스를 종료합니다.

2026-10-06 이전에 만든 `.local`이 있다면 `npm start`를 멈추고 `npm run upgrade:local -- --transparency`를 한 번 실행하세요. OTLP 출처 자격 추가, 데이터 키 분리와 문서 재암호화, 투명성 로그(monitor) 설정을 하며 바꾸는 파일은 먼저 `.local/upgrade-backup-<시각>/`에 복사합니다. `--dry-run`으로 미리 확인할 수 있습니다. [설치·백업·복구 상세](docs/first-release-20261006.md), [권한 패치](docs/first-release-security-patch-20261006.md).

## 검증

핵심 공개 경로부터 확인할 수 있습니다.

```powershell
node --test --test-concurrency=1 test/action-integrity.test.mjs test/receipt-integrity.test.mjs test/governance-authorization.test.mjs test/finance-known-reference.test.mjs test/kr-governance-33-http.test.mjs test/governance-documents.test.mjs test/vault-recovery.test.mjs
```

전체 검사는 `npm test`입니다. 일부 연구 테스트는 공개하지 않는 로컬 학습 영수증·모델 잠금 파일을 요구하며, 해당 파일 묶음이 없으면 경로와 이유를 표시하고 건너뜁니다. 연구 PC에서는 `$env:EVIDSCOPE_REQUIRE_RESEARCH_ARTIFACTS='1'`로 건너뛰기 대신 실패하게 합니다. `npm run check`는 문법·바이트 위생·줄 길이 기준을, `npm run test:ci`는 전체 검사와 CI 판정(실패·취소·이유 없는 건너뛰기 0)을 실행합니다. 모두 통과한 실행은 `.test-runs`에 만든 시험 자격·키를 지우며(진단 파일 `harness-failure-*.json`은 보존), 보존하려면 `$env:EVIDSCOPE_KEEP_TEST_RUNS='1'`을 설정합니다. 새 clone과 과거 설치본의 시험 범위를 구분하고 [검증 안내](docs/verification-status.md)를 확인하세요. Windows 테스트의 IPv6 선택은 `$env:EVIDSCOPE_TEST_HOST='::1'`입니다.

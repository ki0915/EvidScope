# 금융 보고서의 평가 연결 무결성

2026-09-29. 독립 코드 감사에서 서명된 평가 본문은 보존한 채 SQL `evaluations.action_id`만 바꾸면 다른 실행의 평가를 금융 보고서에 연결해 새로 서명할 수 있음을 재현했다. 기존 본문 대조는 조회에 사용하는 실행 ID와 버전을 검증하지 않았다.

`src/finance-evidence.mjs`는 조회·내보내기·보고서 생성 전에 평가 사본의 실행 ID와 버전을 해당 서명 원장 payload에 대조한다. 기존 본문·순서 검증과 동일 SQLite 트랜잭션의 검증/조회/서명은 유지한다. 불일치 시409로 거부한다.

`test/finance-evaluation-binding.test.mjs`는 평가 이동, 두 실행 간 교환, 버전·순서 변경을 검사하고 새 보고서가 저장되지 않으며 서명 이력과 체크포인트가 변하지 않음을 확인한다. 정상 최신 버전 선택과 다른 테넌트 동작도 확인했다. 수정 전3개 실패를 재현한 뒤 수정 후 새5개 및 관련 금융31개가 통과했다.

전체 첫 실행은467개 중465개 통과했다. Windows TLS 테스트의 자식 프로세스가 종료코드3221226505로 종료했다. 제품 코드 변경 없이 같은 TLS8개를 분리 실행해 통과했고, 전체 재실행은 **467/467 통과**했다. 첫 실패 로그를 보존했으며 원인을 코드 회귀나 메모리 문제로 확정하지 않는다.

- 집중 검증: `finance-evaluation-binding-tests-20260929.log`
- 최초 전체: `enterprise-tests-20260929.log`
- TLS 분리 검증: `tls-recheck-20260929.log`
- 최종 전체: `enterprise-tests-final-20260929.log`

수정 제품 이미지 `evidscope:enterprise-20260929-r1`을 빌드하고 이미지 내부 코드로 금융31개를 다시 통과했다. manifest digest는 `sha256:59b5dac57d838aa225c3fb80c51224cb00979a45d9bf8159a98b6a7c6f969c38`다. GPU·네트워크 없이 UID1000, 읽기 전용 루트, CPU2/RAM1GiB로 실행하고 테스트 컨테이너를 제거했다. `finance-container-tests-20260929.log` 참조. 최초 네트워크 차단 빌드는 의존성 조회 EAI_AGAIN으로 실패했고, 정상 빌드는 잠금 의존성의 기존 캐시를 사용해 성공했다. 두 빌드 로그를 보존했다.

합성 데이터와 로컬 서비스/SQLite 검증이다. 외부 금융 시스템 실증, 조직의 법률 충분성 판단, 저장소 고가용성, KMS·불변 보관·운영 SLO나 경쟁 우위 완료를 뜻하지 않는다.

## 실제 실행 검증

공식 KLUE heldout 중 원본 문맥을 유지한 64행(답 있음32/없음32)을 사용했다. 학습·검증과 ID·문서 중복을 배제했다. 두 조건 모두 같은 베이스, 동일 입력, greedy 생성, 입력과 출력 합계1024, 출력128토큰, 요청120초를 적용했다. 제외0, 실제 호출128이다.

## 자원 및 원상 복구

[225회 관측](public-qa-diagnostic-resources-20260929.json): 컨테이너 RAM 최대 약2.00GiB, CUDA allocator 최대 할당 약5.63GiB·예약 약5.79GiB, PC 전체 GPU 메모리 최대8480MiB, GPU 최고74°C, Windows commit 여유 최소6.263GiB, OOM kill0. 서로 다른 메모리 영역을 합산하지 않는다. 이는 추론 평가 수치이며 역전파 학습의 최대 사용량을 뜻하지 않는다.

Docker는 재기동 시 남은 `Docker/run/dockerInference` 소켓 제거 오류를 재현했다. 종료된 Docker 오류 프로세스를 정리하고 0바이트 런타임 소켓 디렉터리 두 개를 `.preserved-20260929-1756` 이름으로 보존한 뒤 엔진29.6.1을 복구했다. 이미지·볼륨·클러스터 초기화는 수행하지 않았다.

읽기 전용 CPU Pod로 평가를 회수한 뒤 보조 Pod를 삭제하고 전용 학습 노드를 정지했다. 실행 lease가 없고, DLP 컨테이너6개가 저장된 ID·원래 실행 상태·restart policy와 일치하며3개 노드 Ready임을 확인했다. 복구 기록은 `.local/training/dlp-restored-20260929.json`에 있다.

## 다음 학습 방향

사용자가 자원 사용량을 낮춰서라도 계속하도록 요청했다. 기존 실제 인코딩384행은 평균639.37토큰이지만 매번1024까지 채웠다. 총393216자리 중147697자리(37.56%)가 패딩이다. 배치별 필요한 길이만 채우면 기존 문맥·정답·학습 마스크를 보존하면서 불필요한 입력 계산과 호스트 배열을 줄일 수 있다. 이 비율을 GPU/RAM 감소 실측치로 해석하지 않는다.

동적 패딩을 구현하고10개 단위 테스트, 실제 고정 이미지의 PyTorch/Transformers CPU 테스트2개를 통과했다. 작은 GPT2 모델에서 고정 패딩과 손실·기울기·유효 토큰 logits의 허용 오차 내 일치를 확인했다. 추가로 실제 토크나이저와384행을 읽어 이전 인코딩 기록의 전 항목 일치와 EOS 보존을 검증했다. 입력 텐서 합계9,437,184→5,892,456바이트를 측정했다. [실제 데이터 검사](public-qa-padding-data-20260929.log), [실제 라이브러리 검사](public-qa-padding-runtime-20260929.log). GPU 역전파 최대 점유는 아직 새 방식으로 측정하지 않았다.

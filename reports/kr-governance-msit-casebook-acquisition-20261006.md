# MSIT AI 기본법 사례집 원본 확보 및 학습 출처 확인

확인일: 2026-10-06. 결과: **공식 사례집 원본과 공개 전문가 검토 근거를 확보하고, 원문 질의응답 48쌍의 후보 범위를 보존했다.** 새 학습은 실행하지 않았다. 이전 출처 조사에서 첨부 원문이 미확인 상태였던 항목의 후속 확인이며, 기존 보고서는 수정하지 않았다.

## 자료별 이용 허가 확인

실제 원 게시물 HTML에서 첨부 파일 목록 바로 다음에 **공공누리 제1유형: 출처표시**와 **AI 유형: 인공지능 학습 가능** 표시가 함께 있다. 일반 푸터를 근거로 허가를 추정하지 않았다. 해당 게시물의 다운로드 함수가 실제 수신한 ZIP과 연결되므로 게시물·허가 표시·첨부 원본을 함께 추적할 수 있다. 그 부분을 `license-post-fragment.html`로 별도 보존했다.

PDF 전체 추출 텍스트의 이용 제한 검색 및 표지·서문·발행 정보 렌더 확인에서는 별도의 공공누리 표시나 본 자료의 복제·학습·재배포 금지 문구를 발견하지 못했다. 이 사실을 모든 삽화·표·제3자 자료의 권리를 전부 조사했다는 주장으로 확대하지 않는다. 이번 후보는 **기관이 발행한 원문 Q/A 텍스트**에 한정한다. 각종 이미지·표의 재배포 권리를 자동 확정하지 않는다.

[한국저작권위원회 유형 안내](https://www.copyright.or.kr/gov/nuri/guide/index.do)에 따라 사용할 유형의 조건과 출처를 데이터·모델 문서에 기록해야 한다. 제1유형은 출처 표시 조건을, 별도 AI유형은 실질적으로 유사한 산출물 방지·직접 인용의 출처 표시 조치·학습용 데이터 재판매 금지 등의 조건을 가진다. 여기서는 게시물에 두 표시가 존재함을 기록했으며, 학습·모델 배포 경로의 조건 충족을 검증했다는 뜻은 아니다.

따라서 **공식 원문 Q/A를 후속 데이터 준비에 사용할 출처·허가 근거가 있는 후보**로 판단한다. 실제 학습 입력으로 바로 승인한 데이터셋은 아니다.

## 공개 전문가 검토 근거와 실제 내용

PDF **7쪽 서문**은 수록 답변이 과학기술정보통신부와 전문기관의 공동 검토 결과를 바탕으로 한다고 명시한다. 실제 접수된 문의의 기관·기업 정보를 익명화·각색했지만 핵심 사실관계 구조를 보존했다는 설명도 있다. **LLM이 새로 만든 정답이 아니라 공식적으로 발행·검토된 상담 사례**라는 근거를 확인했다.

PDF **125쪽**은 주관·운영 기관을 과학기술정보통신부와 한국인공지능·소프트웨어산업협회로, 전문기관을 인공지능안전연구소·한국지능정보사회진흥원·한국정보통신기술협회·정보통신정책연구원으로 표시한다. 개별 답변 검수자의 이름·행별 검수 이력은 알려져 있지 않다. 이 공개 출처 검토 근거와 EvidScope 자체의 사람 검토 기록은 별개이며, **`localHumanReviewPerformed=false`를 유지했다.**

서문은 이 사례집이 **유권해석이 아닌 실무 참고 자료**이고, 실제 서비스·기능 변경·의사결정 구조에 따라 판단이 달라질 수 있다고 명시한다. 부록 법령은 **2026.2. 기준**이므로 현행법 대조 없이 2026-10-06 현재법의 확정 정답으로 쓰지 않는다.

특히 다음 실제 금융·증거 사례를 확인했다.

- **사례 15, PDF 41~42쪽 / 인쇄 33~34쪽:** 대출·신용 심사의 AI 영향과 고영향 해당 판단. 같은 사례의 상세 판단 기준은 PDF 68~69쪽 / 인쇄 60~61쪽에 다시 수록되어 있다.
- **사례 19, PDF 44쪽 / 인쇄 36쪽:** 기록·사후 검증 관리체계. 상세 판단 기준은 PDF 74~75쪽에 수록되어 있다.
- 개인정보·설명 요구 등 피해 대응 Q/A는 PDF 77~78쪽에 있다.

이는 EvidScope의 공급사·배포 모델·사람 감독·문서 보관 판단 설명에 직접 관련된 출처다. 다만 이 자료를 학습했다고 제품의 법률 적합성이나 감사 충분성이 자동 증명되지는 않는다.

## 문항 수와 보존한 후보 범위

실제 PDF의 Q/A 표식을 페이지 순서로 파싱하고 **Q 뒤에 A가 오는 순서**를 확인했다.

| 구역 | PDF 쪽 | 실제 Q/A 쌍 |
|---|---:|---:|
| 제2장 조항별 FAQ | 18~28 | 23 |
| 제3장 대표 상담 사례 | 31~45 | 20 |
| 부록2 기타 피해 대응 안내 | 77~78 | 5 |
| 합계 | | **48** |

20선의 상세 부록은 같은 상담 사례를 다시 풀어 쓴 것이므로 별도 20개 독립 사건으로 세지 않았다. 서로 유사한 FAQ·대표 사례도 있으므로 **48개 독립 학습/평가 가족**이라고 주장하지 않는다. 상담 접수 수 552건과도 구분한다.

`candidate-original-qa-windows.jsonl`에는 새 질문·새 정답·레이블을 생성하지 않고, 각 Q/A의 **원본 페이지·문자 위치·원문 구간·구간 해시·원본 PDF 해시·동일 문서 가족**을 보존했다. 별도 질문/정답 학습 텐서를 만들지 않았다. 문항 사이의 제목·핵심 포인트·표·풋터가 포함될 수 있는 원문 범위이므로 **`boundaryReviewRequired=true`**, **`trainingReady=false`**다. 실제 원문을 대조하여 경계를 정하는 다음 단계의 입력이다.

검사 결과: 48개 고유 후보 ID, 48개의 Q/A 순서 일치, 모든 원문 구간의 PDF 재추출 문자 범위와 해시 일치. **사례 13의 Q가 PDF 39쪽, A가 40쪽으로 넘어가는 연결도 보존했다.** 원문 PDF 해시와 전체 페이지 텍스트를 다시 읽어 확인하므로 추출 파일만 바꿔 통과하는 경로가 아니다. 서문·발행 정보·금융 사례·구역 끝·문항의 페이지 경계를 렌더하여 확인했다.

원문에는 기관의 공개 상담 전화·URL도 있으므로 개인정보 검사와 자료 경계 검토를 수행하기 전 학습 게이트에 넣지 않는다. 같은 문서 및 상담 가족을 학습과 평가로 나눠 넣지 않는다. 분할은 아직 만들지 않았다.

## 상태와 실행 범위

- 공개 전문가 검토 근거 및 자료별 허가 표시 확보: **완료**.
- PDF 원본·게시물 HTML·출처 해시 및 원문 후보 범위 48건 보존: **완료**.
- 문항 경계 확정·개인정보 검사·현행법 대조·독립 평가 자료/분할·학습 입력 승인: **미실행**.
- `localHumanReviewPerformed=false`, `qualityClaimAllowed=false`, `promotionAllowed=false`, `trainingPerformed=false` 유지.
- 기존 모델·학습 런타임·Docker·Kubernetes·GPU·PVC·사용자 PC 메모리 설정은 변경하지 않았다. CPU의 소형 PDF 파싱·선택 페이지 렌더만 수행했다.

처음 PDF 출력 확인에서는 콘솔 CP949 인코딩 오류가 발생했지만 원문 추출 파일은 이미 저장되어 있었다. UTF-8 콘솔을 명시한 재확인으로 실제 내용을 읽었다. 후속 인라인 검증의 PowerShell 따옴표 오류는 파일 형태의 검증 스크립트로 수정하여 수행했다. 원본 파일 또는 실패를 성공으로 간주하지 않았다.
